# Oracle provider behavior and limitations

## Connection retries

Oracle query connections use the shared retry policy (two retries with exponential backoff) for transient connection failures, including unavailable listeners, connection timeouts, and database startup/shutdown. Authentication, invalid connection identifiers, and constraint errors are not retried.

## Application name

Query and metadata sessions identify DAB through Oracle's `MODULE` session attribute, using `DAB_APP_NAME_ENV` when set or the default DAB user agent. The name is limited to 48 UTF-8 bytes without splitting characters and is reapplied on each connection open.

## Binary columns

`RAW` and `BLOB` columns use base64 strings in REST and GraphQL, including mutation responses and nested relationships. Input values must also be base64 strings. `RAW(16)` keys are exposed as the stored 16 bytes encoded in base64; they are not converted to formatted UUID strings.

RAW keys support point reads and cursor pagination. Binary-field filters retain DAB's existing null checks; this support does not add binary equality or ordering filter operators. BLOB values are encoded in chunks so large values are not truncated by Oracle's scalar string limits. A null BLOB is JSON `null`; an empty BLOB is the empty string. Oracle treats an empty RAW value as null.

Read conversion uses statement-local functions and the Oracle `DBMS_LOB`, `UTL_ENCODE`, and `UTL_RAW` packages. The database user must be allowed to execute these packages; no stored function installation or `CREATE FUNCTION` privilege is required.

`LONG RAW` remains unsupported and is rejected during metadata initialization. Migrate it to `BLOB` or expose supported text through a view.

## Identity columns

Identity columns declared `GENERATED ALWAYS` are read-only; `GENERATED BY DEFAULT` and `GENERATED BY DEFAULT ON NULL` allow explicit values as well as database-generated values.

## JSON values

`NUMBER(1)` flags remain JSON numbers (`0`/`1`), not inferred Booleans. Empty Oracle character strings become null.

As described in the [Oracle SQL/JSON generation rules](https://docs.oracle.com/en/database/oracle/oracle-database/19/adjsn/generation.html), non-finite doubles are emitted as the JSON strings `"Inf"`, `"-Inf"`, or `"Nan"`; REST preserves these strings, while GraphQL reports a field-mapping error because its `Float` scalar cannot represent them.
